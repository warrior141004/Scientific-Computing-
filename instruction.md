You are fitting a one-dimensional magnetotelluric sounding for a dispersive layered earth. The acquisition software did not preserve physical frequency; it recorded a nonlinear instrument tick instead. Recover the clock, undo the station electronics, fit the earth model, and predict impedances for held-out ticks.

Write a complete C++17 program at `/app/solve.cpp`. Harbor compiles it with `g++ -std=c++17 -O2 -pipe` and invokes it as `/app/solve <path-to-manifest>`. The current working directory is writable. Your program must create `state/clock.tsv`, `state/gains.tsv`, `state/model.tsv`, `state/predictions.tsv`, and `answers.tsv` there. Do not use Python, the network, a hard-coded absolute input path, or public-bundle constants. The hidden bundles use the same format but change the clock, stations, electronics, and earth parameters.

The manifest is a whitespace-separated list of relative paths, one for each of `constants`, `model`, `clock`, `stations`, `calibration`, `observations`, and `queries`. Ignore blank lines and comments beginning with `#`, and resolve every path relative to the manifest file rather than relative to the process directory.

`constants.cfg` contains `mu0`, `pi`, and `huber_delta`, and may also contain `clock_order`. Use those values in the calculation; if `clock_order` is absent, use order 2. `model.cfg` contains `layer_count`, `dispersive_layer`, initial values, and lower and upper bounds. The physical parameters are three layer resistivities `rho0..rho2` in ohm-metres, two finite-layer thicknesses `h0,h1` in metres, chargeability `m`, relaxation time `tau` in seconds, and Cole-Cole exponent `c`. The final layer is a half-space. The supplied bundles have three layers, although the file still declares the count. The declared `dispersive_layer` may be any of the three layers, including the half-space.

The clock file contains rows `beacon_id instrument_tick known_frequency_hz`. The hidden relation is a polynomial in `x = log(frequency_hz)`: `tick = a0 + a1*x + ... + aK*x^K`, where `K` is `clock_order`; the coefficients are deliberately omitted. Recover the coefficients from all beacon rows. To turn an observation or query tick back into frequency, invert that polynomial in `x`. Use the positive-frequency root on the beacon-covered monotone branch, meaning the root whose derivative with respect to `x` is positive. Choosing the other root will produce a plausible-looking but completely wrong inversion.

`stations.tsv` contains `station_id orientation_degrees`. The orientation is counter-clockwise from the station's measured horizontal axis to the earth frame. Calibration rows have the form `station_id frequency reference_re reference_im measured_re measured_im`. For one station, every row follows the same analog response:

`measured = gain * (1 + i*2*pi*frequency*zero_tau) / (1 + i*2*pi*frequency*pole_tau) * reference`.

`gain` is complex, while `pole_tau` and `zero_tau` are nonnegative real time constants shared by all rows for the station. Calibration has no noise. Use the full frequency sweep to recover `pole_tau` in `[0,0.02]` seconds and `zero_tau` in `[0,0.012]` seconds. For any trial pair, remove the trial response from each measured value and estimate the gain with

`gain = sum(measured*(1+i*2*pi*frequency*pole_tau)/(1+i*2*pi*frequency*zero_tau)*conjugate(reference)) / sum(|reference|^2)`.

This is an electronics reverse-engineering step; dividing one calibration row is insufficient because the pole and zero can compensate each other at a single frequency.

An observation row is `observation_id station_id instrument_tick raw_re raw_im`. Observation and query IDs are not guaranteed to be contiguous or zero-based; preserve the IDs and input order in the output files. First convert its tick to frequency. Then remove the pole and gain and rotate back to earth coordinates. If `r` is the raw complex value, the calibrated observation is

`z_obs = r*(1+i*2*pi*frequency*pole_tau)/(gain*(1+i*2*pi*frequency*zero_tau))/exp(i*orientation*pi/180)`.

The observations contain small additive noise and one deliberately large outlier per bundle. The outlier is not marked. A query row is `query_id station_id instrument_tick`; queries are in input order and ask for the earth-frame impedance.

For a candidate earth model, let `omega = 2*pi*frequency` and start with `sigma_j = 1/rho_j`. For the declared dispersive layer `d`, replace that conductivity with `sigma_d*(1 + m/(1 + (i*omega*tau)^c))`. Use the principal complex power, `z^c = exp(c*log(z))`, and the principal complex square root. Define `gamma_j = sqrt(i*omega*mu0*sigma_j)` and `eta_j = sqrt(i*omega*mu0/sigma_j)`. Start at the bottom half-space with `Z = eta_(N-1)`. For `j = N-2` down to `0`, compute `t = tanh(gamma_j*thickness_j)` and then update `Z = eta_j*(Z + eta_j*t)/(eta_j + Z*t)`. The resulting `Z` is the earth-frame surface impedance. The order of this downward recursion matters.

Compare a model with each calibrated observation in log-polar form. Use `logamp = log10(abs(Z))` and `phase_deg = atan2(imag(Z),real(Z))*180/pi`, keeping phase in `[-180,180]`. The amplitude residual is predicted logamp minus observed logamp. The phase residual is the circular difference, in `[-180,180)`, multiplied by `pi/180`. If `r = hypot(amplitude_residual, phase_residual)` and `delta = huber_delta`, the contribution is `0.5*r*r` for `r <= delta` and `delta*r - 0.5*delta*delta` otherwise. Minimize the sum within the model bounds. Calibrate the shared station responses before fitting the earth; do not introduce an independent gain for every frequency.

The intermediate files are part of the task, not documentation. Write `state/clock.tsv` first with `a0 value` through `aK value`, one coefficient per line in ascending order. Write `state/gains.tsv` in first-appearance station order as `station_id gain_re gain_im pole_tau zero_tau calibration_rms`, where the last field is the RMS complex calibration residual. Write `state/model.tsv` with the lines `rho0 value`, `rho1 value`, `rho2 value`, `h0 value`, `h1 value`, `m value`, `tau value`, `c value`, and `objective value`, in that order. Write `state/predictions.tsv` in observation order as `observation_id predicted_logamp predicted_phase_deg residual_logamp residual_phase_deg`, wrapping the phase residual to `[-180,180)`. Finally write `answers.tsv` in query order as `query_id predicted_logamp predicted_phase_deg`. Do not add prose to these files; standard output is ignored. Missing state, wrong row order, or an incorrect intermediate calculation fails even when a final query happens to be close.
